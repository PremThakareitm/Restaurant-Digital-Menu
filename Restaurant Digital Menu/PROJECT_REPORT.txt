 1. PROBLEM UNDERSTANDING
────────────────────────────────────────────────────────────────────────────────

CASE STUDY:
   Restaurants traditionally hand out physical menus to customers, which are
   costly to reprint whenever items change, prone to damage, and unable to
   provide rich information like ingredient lists, ratings, or photos. Customers
   also have no convenient way to browse, favourite items, or place orders from
   their seat.

OBJECTIVE:
   Design and build a fully functional digital menu application for a restaurant
   ("Bites & Brilliance") that:

   • Replaces the physical menu with a beautiful, interactive mobile app.
   • Allows customers to browse dishes by category, filter by veg / spicy /
     bestseller, and search for specific items.
   • Provides rich dish detail pages with photos, ingredients, ratings, and
     pricing.
   • Lets customers add items to a cart, specify a table number or takeaway
     option, add special instructions, and place a confirmed order.
   • Allows customers to save favourite dishes for quick future access.
   • Presents restaurant information (contact, hours, gallery, address).

   The solution is built with Flutter for cross-platform reach (Android, iOS,
   and Web from a single codebase), backed by a Node.js/Express REST API that
   serves dish and restaurant data.

3.4 STATE MANAGEMENT (AppState)
─────────────────────────────────
   AppState (ChangeNotifier) holds:
   • dishes          — all 23 Dish objects from MenuData
   • selectedCategory — active category filter ('all', 'starter', etc.)
   • searchQuery     — live search text
   • searchVisible   — whether search bar is showing
   • filterVeg / filterSpicy / filterBestseller — boolean toggles
   • favorites       — Set<String> of dish IDs
   • _order          — Map<String, OrderItem> (dish ID → OrderItem)
   • tableNumber     — nullable int (0=Takeaway, 1–15=table)
   • orderNote       — special instructions string
   • _orderHistory   — List<PlacedOrder> (session-only)

   Computed getters:
   • filteredDishes  — applies all active filters simultaneously
   • trendingDishes  — dishes where isBestseller == true
   • totalOrderItems — sum of all quantities in cart
   • totalOrderPrice — sum of all (price × qty) in cart
   • favoriteDishes  — dishes filtered by favorite set
   • orderItems      — list of OrderItem values from cart map

5.1 APPLICATION WORKFLOW
──────────────────────────

   STEP 1 — Launch
   A customer opens the app. They see the animated splash screen for ~2.5 seconds
   while the app initializes, then smoothly transitions to the home screen.

   STEP 2 — Browse the Menu
   The Menu tab is the default. The customer can:
   (a) Scroll down to see all dishes in a visual grid.
   (b) Tap a Category Tab (e.g., 🍛 Main Course) to filter by category.
   (c) Enable filters: 🌿 Veg Only, 🌶️ Spicy, or ⭐ Bestseller.
   (d) Tap the search icon to type a dish name or ingredient.
   (e) Scroll the "Trending Now" strip to discover popular items.

   STEP 3 — View Dish Detail
   Tapping any dish card opens the DishDetailScreen:
   • Swipe through multiple photos.
   • Read the description and ingredient list.
   • Check the star rating and review count.
   • Use the +/− stepper or the sticky "Add to Order" button to add to cart.
   • Tap the heart icon to save to Favourites.
   • Tap the back arrow to return to the menu.

   STEP 4 — Manage Favourites
   The Favourites tab shows all dishes the user has liked. Tapping any item
   opens its detail. The empty state guides new users to explore the menu.

   STEP 5 — Build the Order
   The Order tab (with a live count badge) shows:
   • All cart items with quantities and per-item totals.
   • Table selection (Takeaway or any of 15 tables).
   • An optional special instructions note.
   The running subtotal, GST, and total are shown in real time.

   STEP 6 — Place the Order
   Tapping "Place Order" generates a confirmation dialog showing:
   • A unique 6-character alphanumeric order token.
   • Order summary (items, total, wait time).
   • Table or Takeaway detail.
   The token can be copied and presented at the counter. The cart is cleared
   automatically, and the placed order is added to Order History.

   STEP 7 — Restaurant Information
   The About tab details the restaurant: address, hours, phone, email,
   website, and a photo gallery for ambiance reference.

5.3 BACKEND API DOCUMENTATION
───────────────────────────────

   Base URL: http://localhost:5000/api

   Endpoint               Method  Description
   ─────────────────────  ──────  ──────────────────────────────────────────
   /health                GET     Server health check
   /dishes                GET     List dishes (filters: category, search,
                                  veg, spicy, bestseller, sort, page, limit)
   /dishes/:id            GET     Get single dish by ID
   /categories            GET     List categories with dish counts
   /restaurant            GET     Restaurant metadata (name, hours, contact)
   /orders                POST    Submit order, returns token + total + tax

   POST /api/orders — Request Body:
   {
     "items": [
       { "dishId": "chicken-tikka", "quantity": 2 },
       { "dishId": "butter-chicken", "quantity": 1 }
     ]
   }

   POST /api/orders — Response:
   {
     "success": true,
     "token": "ORD-1234567890",
     "items": [...],
     "subtotal": 997,
     "tax": 79.76,
     "total": 1076.76,
     "estimatedWait": "30 minutes"
   }

5.4 KNOWN LIMITATIONS
──────────────────────
   • Dish data is currently static (Dart constants) — backend integration
     would enable real-time menu updates without app rebuild.
   • Tax rate discrepancy: frontend uses 5% GST; backend uses 8%. Should
     be unified via a shared configuration or API response.
   • Order history is session-only (in-memory); a database would persist orders.
   • No user authentication or table booking system implemented.
   • Images are sourced from Unsplash CDN and require internet connectivity.
